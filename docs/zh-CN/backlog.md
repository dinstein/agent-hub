## 缺口一览

**空。** 目前没有任何跨平台缺口被定位到行。

这不是在宣称代码没有毛病——它的意思是当下没有任何一条达到上面那条收录标准。
2026-07-30 清掉了两条：

- **`internal/daemon` HTTP 数据面用例在重负载下超时。** 2026-07-29 在人为制造的 CPU 争抢下
  （24 个 `yes` 进程、`-count=20 -race`）复现过 2 次，此后约 48 次运行再未复现。
  按「不值得继续跟踪」关掉，而不是按「已定位根因」关掉。取证路径仍然在：超时时
  `waitForDetail`（`internal/daemon/daemon_test.go`）会打印最后一次观测以及全部 goroutine 栈。
  万一它再出现，**先拿到一次带栈的失败**再动 `testTimeout`——调大超时会把它变成
  「更慢地偶发失败」，并删掉区分「真卡住」与「20 次 daemon 冷启动确实不止 10s」的唯一线索。
- **Windows 控制管道不区分构建渠道。** 代码里依然成立（`windowsCtlEndpoint`,
  `internal/platform/windows.go`），现已完整记入 [windows.md](windows.md)——包括为什么不能把
  渠道拼进现有管道名——那里本来就是其余「未验证平台」工作的归属地。
  `TestDevResolverSeparatesFromRelease` 的 windows 行继续带着 `endpointSeparates: false`，
  所以这条缺口仍然有人看守。

## 附：这些缺口是怎么发现的

本文曾经收录的那些条目，是 2026-07-27 一次会话中，接入两台真实 MCP 服务器
（均走同一套企业 SSO OAuth）的过程里暴露的。同批发现的三个**已修复**问题：

| commit | 问题 |
|---|---|
| `5272d44` | `--issuer` 对所有远程服务器完全失效（`ResourceURL` 无条件优先） |
| `f2ac941` | `server add --stdin` 静默丢弃 `oauth` 块（`stdinEntry` 未建模该字段） |
| `e8cbb28` | RFC 9728 候选漏了 origin 根路径 |

值得记下的教训：`normalizeStdin` **此前零测试覆盖**，这正是静默丢字段能长期存活的原因。
修复时一并加了 `DisallowUnknownFields`——未建模的键现在直接报错，
而不是无声丢弃后让失败推迟到几步之外、以看似无关的面貌出现。
