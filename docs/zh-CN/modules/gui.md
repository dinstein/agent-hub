# GUI 前端

按**外部约束**而非按层组织的第二篇专题（另一篇是 [oauth.md](oauth.md)）。
本文讲 `cmd/agenthub-gui/frontend/` 这 ~10k 行 TypeScript 的判断依据：
**为什么它长这样、哪些规则不能顺手改**。Go 侧的服务体与装配在
[controlplane.md](controlplane.md#cmdagenthub-gui)。

技术栈的裁决理由（vanilla TS + Vite、只有 `@wailsio/runtime` 一个运行时依赖、
把 alpha 依赖压缩到两个文件）在 [../canonical.md](../canonical.md) §7 第 3 项。

---

## 1. 信息架构：按「要不要你管」组织，不按领域模型

侧栏一开始是 CLI 命令树的一比一映射——十四张资源表，按领域模型排列。
这是给知道自己在找什么的人用的；对刚接上第一台 server 的人，它要求你先学会我们的对象模型。

现在的判断是：**列表按状态分桶，不按字母**。server 列表分三桶——需处理 / 活跃 / 已禁用——
桶内再排序，**空桶不渲染**，已禁用默认折叠（折叠状态存 localStorage）。
顶部一行概览 chips（`20 servers · 13 connected · 1 needs attention · 6 disabled`），
**计数为零的 chip 直接不出现**（`dom.ts` 的 `chip()` 对 0 返回 `null`，由 `chipRow` 丢弃）。
「0 needs attention」是噪音，不是信息。

## 2. 状态即行动

一行 server 的状态位有五态，每态用**三个通道同时表达**（点的颜色 / 文案内容 / 文案颜色）——
颜色永远不是唯一通道，这既是无障碍要求也是防误读：

| 状态 | 显示 |
|---|---|
| connected | **`23 tools`** —— 不写 "connected"。有信息量的数字顶掉冗余状态词 |
| needs-auth | 状态位整个**换成 `Authenticate` 按钮**，点了真的登录（§2.1） |
| checking | 超过 4 秒且命令是 `npx`/`uvx` 时改成 **`Installing…`** —— 把等待重解释成进度 |
| error | 一行提炼的错误标题 + 展开看全文 |
| disabled | 灰点，无文案 |

这条最省用户时间：不需要「看状态 → 想该干什么 → 找入口」三步。

**语义色只给健康状态。** transport、来源、profile 这类元数据一律中性色
（`ChipTone` 的 `neutral`）。否则一台健康的 stdio server 会同时出现两个不相干的绿点，
颜色就不再有意义。

**Health 一律渲染，绝不再推导。** 等级由 daemon 的纯函数算出，前端只显示；
常量从 `api` 包生成到 `generated/health.ts`，golden 测试盯着它防三端漂移。
前端拿连接标志自己拼一个状态，就是第二份判定。

**全局开关是开关，不是动词。** 启用/停用原先是行尾四个同款按钮里的一个词，这把本页最常用的设置
搞错了两次：它落在视线最后到的位置，而且它说的是**动作**而不是**当前值**——当作标签来读，"Disable"
标记的是那些开着的 server。现在它在行首。

它上面有两条规矩，都很容易被顺手改坏：

- **「开」的颜色是 `--accent`（墨色），绝不是 `--success`。** 绿色轨道会在一行里放上第二个绿，而这
  一行已经有一个绿色的健康点了，两者含义无关——「你把它打开了」对「它真的在工作」。别家产品的开关
  都是绿的，所以这条写在 `style.css` 里别人会去「修」它的那个位置。
- **开关的位置永远不由点击决定。** `onChange` 去发写请求，页面从返回结果重画，所以被拒绝的写、失效
  的 precondition、被取消的确认框，都会让开关停在**已存储**的那个值上。乐观翻转是要往回撤的，而它
  错着的那一刻恰好就是用户满意地把视线移开的那一刻——和审批行「变灰而不是消失」是同一个理由（§5）。

### 2.1 Authenticate 按钮真的会登录

它原先弹出的对话框，全部内容是「GUI 没有能做这件事的端点，请去终端跑 `agenthub auth login`」——
而这个应用的立足点正是客户端不碰凭据。现在控制面提供了登录
（[controlplane.md](controlplane.md#面上唯一的长流程交换交互式登录)），本页负责驱动它。

- **第一瞬间刻意什么都不显示。** 在 device 与 loopback 之间做选择需要授权服务器的 metadata，所以那
  时候确实没什么可说的。这个状态会说明它在等什么，而不是围着一个用户之后还得重新理解的、凭空编出来
  的模式转圈。
- **由本页打开宿主浏览器**，绝不用这个 webview。把授权页渲染在应用里，就是 agenthub 在一个由
  agenthub 控制的窗口里索要 provider 密码：那是钓鱼页的形状，并且拿掉了地址栏、锁，以及密码管理器
  拒绝在错误 origin 上填充这三重保护。
- **loopback URL 只打开一次**，按值记录——每次轮询都打开会让用户的浏览器每 700ms 多出一个授权页。
- **关掉窗口只取消「等待」，别的什么都不取消**；而且会话一旦终结就不再发取消：对一件已经成功的事
  请求放弃，是一个没有正确答案的问题。
- **失败会明说什么都没存下**，带上流程自己的建议，并给一个重试入口，用户不会被留在「这台 server 现
  在是不是半授权状态」的猜测里。
- **device code 用大号等宽字体并加了字距。** 它是本应用里唯一需要人往另一个窗口里重新敲一遍的字符
  串，`O`/`0` 和 `I`/`l` 必须一眼就能分开，而不是敲错一次之后才分开。

## 3. 错误与空态

**错误提炼 + 全文可复制。** daemon 返回的错误常常是一整坨 stack 或超长 URL。
`dom.ts` 的 `errorHeadline()` 是个纯函数，把它压成一行标题
（`Command or file not found (ENOENT)` / `Port already in use (127.0.0.1:39541)` /
`Authentication required (401)`），全文保留在下方可滚动区，右上角一个 Copy。

**空态分三种，不是一种**（`EmptyKind = "loading" | "failed" | "empty"`）：

| 种类 | 渲染 |
|---|---|
| `loading` | 骨架行 |
| `failed` | 带 Retry，并**明说「这不是空」** |
| `empty` | 带下一步 CTA |

把「网络故障」伪装成「注册表里没有这个」是这套 UI 最容易犯、也最难被发现的错——
用户会去找一台他明明配过的 server，然后怀疑自己的记忆。

## 4. 写操作的表现层

**确认对话框的文案模式**：标题是问句（`Remove stripe?`），按钮是动词（`Remove`），
描述里说明**什么不会发生**（「凭据仍留在钥匙串里」）。失败时对话框**保持打开**；
批量操作带阈值（超过 3 个才确认）；**过滤状态下禁用全局操作**——否则会动到看不见的行。

**409 冲突不覆盖。** 控制面的写端点带 `Precondition`，冲突返回 409 + 当前 generation
（见 [../flows.md §4](../flows.md#4-配置写入五个写者与乐观锁)）。前端收到就重新拉取并提示
「配置已被其他地方修改，已刷新」（`page.ts` 的 `CONFLICT_MESSAGE`），而不是把用户几分钟前的
视图写回去。

**写完之后不轮询。** 写入 bump generation，watcher 发事件，控制面经 SSE 推回来，页面据此刷新。
自己写的和别人写的走同一条回路，所以两者在界面上表现一致。

**凭据永不回显。** 输入框是 password 类型，提交后立即清空，**没有「显示明文」开关**。
读取端点返回的类型里根本没有 value 字段。agent token 原文只在创建成功的那个对话框里出现一次，
并明确写「关掉就再也看不到了」。

## 5. HITL 的表现层

审批面板是整个 GUI 里最不能将就的一块，而它全是 DOM + CSS：

- 顶部固定、**不阻塞**其余界面（`role="alertdialog"` 但 `aria-modal="false"`）——
  一个把整个窗口锁住的审批框，会让人为了看清上下文而先点掉它
- 副标题直接写死机制：**「3 tool calls held — no decision auto-denies」**。
  fail-closed 写在界面上，而不是只写在文档里
- 倒计时用进度条 + 秒数双通道，≤20 秒变红
- **Esc = 拒绝最早那条**（拒绝是安全方向）
- 三档决策：本次 / 本会话 / 永久——治审批疲劳
- **决策不做乐观移除**：点完变灰等后端确认，否则会「闪回」成未决

**隔离告警的 dismiss 作用域是内容签名**（工具名 + 时间戳的哈希），不是一个布尔。
所以一个被忽略过、后来又漂移的工具**会重新弹出来**。侧栏常驻的计数 badge 兜底可发现性。

**静息态卡片**：什么问题都没有时，显示一条灰色的「正在监视工具篡改、投毒与注入输出，
目前没有问题」。成本几乎为零，但**用户看不见的保护不产生信任**。

## 6. 每个操作旁边显示等价的 CLI 命令

```
[Remove]  ⌘  agenthub server rm stripe
```

这是**硬约束送的差异化**。「GUI 不能有 CLI 没有的能力」意味着每个 GUI 操作**必然存在**
一条等价命令，那就把它显示出来并支持复制。顺手解决两个真实需求：高级用户想脚本化，
以及用户想把操作贴进文档或工单。

副作用是 **GUI 成了 CLI 的教学界面**——用户点几次就知道命令长什么样了。

## 7. 明确不做

**不用 React + shadcn 重写。** 代价具体化：运行时依赖从 1 个变成约 13 个直接依赖加数百个传递
依赖。对一个**安全网关**产品，这个供应链面积是反讽的——我们在 UI 里检测投毒和篡改，
同时把几百个 npm 包塞进自己的构建。

真正想要的「看起来像样」，95% 的收益来自三样东西：**一组语义色 CSS 变量、一个统一的 focus ring、
button/input/dialog 三套 CSS 类**。三样都不需要框架。

其余不采纳的：Radix 全家桶（原生 `<dialog>` 自带模态 / Esc / 焦点陷阱）、Tailwind、
`lucide-react`（改成编译期内联实际用到的那二十几个 SVG，零运行时依赖）。

**两处刻意不抄的失败**：

- **不做「垃圾抽屉」页**——九种不同抽象层级的东西竖着堆一页、全靠默认折叠抢救，
  想回答「刚才那次调用为什么失败」就要滚过一堆无关内容。Audit 分 Overview / Calls / Security 三段。
- **营销文案不进产品界面**——省下的 token 是合理指标，但包装成美元估算再配 Share 按钮是在
  向用户索取传播；而且硬编码的模型价目表一定会过时。**一个过时的美元数字比没有数字更糟**：
  在一个专门检测「东西悄悄变了」的产品里，它自己就是个会悄悄变错的东西。

## 8. 文件地图

| 文件 | 内容 |
|---|---|
| `main.ts` | 入口：主题 bootstrap、路由、侧栏、SSE 订阅 |
| `bridge.ts` | 与 Go 侧的唯一接缝：`Call.ByName(<Go FQN>)` + `Events.On`（不用 `wails3 generate bindings`），以及 `openExternal`——走宿主浏览器，绝不走这个 webview |
| `page.ts` | `Page` 契约、`failureBox` / `failureState`、`CONFLICT_MESSAGE`、`noticeSlot` |
| `dom.ts` | 无依赖 DOM 构造：`el` / `table` / `emptyState`（三态）/ `chip`（0 返回 null）/ `errorHeadline` / 时间格式化 |
| `ui.ts` | 表单件：输入、三态选择器、pair/lines 编辑器、确认对话框、`toggleSwitch`（绝不乐观翻转） |
| `types.ts` | 控制面 DTO 的 TS 镜像 |
| `generated/health.ts` | **生成物**：Health 的 Level/AdminState/Action 常量，`go generate ./cmd/agenthub-gui/...` |
| `pages/*.ts` | 每个资源一页，17 页 |
| `style.css` | 语义色变量、focus ring、三套控件类、light/dark |

深色模式由 `index.html` 里的内联 bootstrap 脚本在首帧前打上主题类（防闪白），
light / dark / system 三态，约 20 行原生 JS 加两组 CSS 变量。
