# MCP 2026-07-28 支持

本文记录 AgentHub 支持 MCP 2026-07-28 规范的调研、设计决策和实现计划，是
`mcp-2026-07-28` 分支的主要参考文档。英文原文见
[docs/mcp-2026-07-28.md](../mcp-2026-07-28.md)。

上游规范：<https://modelcontextprotocol.io/specification/2026-07-28>
相对 2025-11-25 的变更日志：<https://modelcontextprotocol.io/specification/2026-07-28/changelog>

## 1. 变更内容及对本代码库的影响

### 1.1 破坏性变更（连接 2026-07-28 server 前必须修改）

#### 无状态协议——移除 `initialize` 握手

`initialize` / `notifications/initialized` 往返不再存在。每个出站请求改为在
`_meta` 字段中携带三个键：

| 键 | 是否必须 | 内容 |
|----|----------|------|
| `io.modelcontextprotocol/protocolVersion` | 是 | `"2026-07-28"` |
| `io.modelcontextprotocol/clientCapabilities` | 是 | `ClientCapabilities` 对象 |
| `io.modelcontextprotocol/clientInfo` | 应当 | `Implementation` 对象 |

服务端应在每个 result 的 `_meta` 中回传 `io.modelcontextprotocol/serverInfo`。
缺少必填字段的请求以 `-32602`（Invalid params）拒绝，HTTP 传输层返回 400。

**向后兼容规则**：当 `NegotiateVersion` 确认服务端使用 2025-11-25 或更早版本时，
旧有的 Initialize 路径保持不变。版本通过 `server/discover` 确定；若该 RPC 不存在
（stdio 探针），则回退到 `initialize`。

#### `server/discover`——新增必要 RPC

服务端**必须**实现该 RPC，返回支持的协议版本列表、能力集和服务端身份。客户端可
在发送任意其他请求前调用，以选择双方都支持的最高版本。在 stdio 下也可作为向后兼容
探针：服务端不响应 `server/discover` 时，调用方回退到 `initialize`。

#### 所有 Result 必须携带 `resultType` 字段

每个 result 对象必须带 `resultType`：

- `"complete"` — 正常的成功结果
- `"input_required"` — 服务端需要更多信息（见 MRTR 小节）

向后兼容：来自 2025-11-25 服务端且缺少该字段的结果，视为 `"complete"`。

#### 多轮交互请求（MRTR）——取代服务端发起的 RPC

服务端发起请求（`roots/list`、`sampling/createMessage`、`elicitation/create`）
的旧有模式已**移除**。需要客户端输入的服务端，改为在 `tools/call`、`prompts/get`
或 `resources/read` 的响应中返回 `InputRequiredResult`。

客户端必须：
1. 收集所请求的输入。
2. 用**新的** JSON-RPC id 重试原始请求，携带 `inputResponses` 和回传的
   `requestState`。

客户端不得检查或修改 `requestState`；服务端负责其完整性保护。

#### Streamable HTTP：移除 session ID 和可恢复性

- `Mcp-Session-Id` 头彻底消失——不再有 session 捕获，Close 时也不再 DELETE。
- `Last-Event-ID` 和 SSE event ID 消失——响应流中断即请求丢失，客户端**必须**用
  新请求 ID 重新发起。
- HTTP GET 的带外通知端点由 `subscriptions/listen` 取代。

#### `subscriptions/listen`——新订阅流

单一长连接 POST 响应流取代 GET 通知流及 `resources/subscribe` /
`resources/unsubscribe`。客户端选择订阅的事件类型：
`toolsListChanged`、`promptsListChanged`、`resourcesListChanged`、
`resourceSubscriptions`。流上的每条通知在 `_meta` 中携带
`io.modelcontextprotocol/subscriptionId` 用于关联。

#### 已移除的方法

| 已移除 | 替代方案 |
|--------|----------|
| `ping` | （无，直接省略） |
| `logging/setLevel` | 请求 `_meta` 中的 `io.modelcontextprotocol/logLevel` |
| `notifications/roots/list_changed` | （已废弃——改用 MRTR） |
| `resources/subscribe`、`resources/unsubscribe` | `subscriptions/listen` |
| HTTP GET 通知流 | `subscriptions/listen` |

#### 错误码重编

| 错误码 | 名称 | 旧错误码 |
|--------|------|----------|
| `-32020` | `HeaderMismatch` | `-32001` |
| `-32021` | `MissingRequiredClientCapability` | `-32003` |
| `-32022` | `UnsupportedProtocolVersion` | `-32004` |
| `-32602` | 资源未找到（JSON-RPC Invalid Params） | `-32002` |

`-32000` 到 `-32019` 现为"遗留"区间（已有 SDK 用法被接受，不再新增分配）。
`-32020` 到 `-32099` 保留给 MCP 规范。

#### Streamable HTTP 必须携带的请求头

每个 POST 请求现在必须携带：
- `Mcp-Method`：JSON-RPC 方法名
- `Mcp-Name`：工具 / 资源 / 提示词名称（适用时）

### 1.2 新增小变更

- **`CacheableResult`**：`tools/list`、`resources/list`、`prompts/list`、
  `resources/read`、`resources/templates/list` 的结果必须携带 `ttlMs`（毫秒新鲜度
  提示）和 `cacheScope`（`"public"` 或 `"private"`）。
- **`extensions` 字段**加入 `ClientCapabilities` / `ServerCapabilities`，用于
  核心协议之外的可选扩展协商。
- **Tasks** 从实验性升为正式扩展 `io.modelcontextprotocol/tasks`；改为轮询
  （`tasks/get`）和客户端到服务端输入（`tasks/update`）。
- **`tools/list` 应返回确定性顺序**，以提升 LLM prompt 缓存命中率。
- **OpenTelemetry**：`traceparent`、`tracestate`、`baggage` 按 W3C Trace Context
  规范进入 `_meta`。
- **OAuth `iss` 校验**（RFC 9207）：认证响应应携带 `iss`；客户端在兑换授权码前
  必须对比已记录的 issuer 校验该值。
- **`application_type`** DCR 请求中为必填。
- **Client ID Metadata Documents** 作为 DCR 的首选替代方案。

### 1.3 废弃项（至少 12 个月窗口，最早 2027-07-28 移除）

| 特性 | 迁移方向 |
|------|----------|
| `roots` 特性 | 通过工具参数、资源 URI 或服务端配置传递目录 |
| `sampling` 特性 | 直接与 LLM 提供商 API 集成 |
| `logging` 特性 | 写入 `stderr`（stdio）或使用 OpenTelemetry |
| HTTP+SSE transport | 代码中已标 `DEPRECATED-UPSTREAM`；迁移到 Streamable HTTP |
| OAuth DCR（RFC 7591） | 使用 Client ID Metadata Documents |

## 2. 实现计划

工作按依赖关系分三期。每期产出一个或多个 commit，每个 commit 均能编译且通过
`make ci`。

### Phase 1 — 传输层（目标：2 周）

目标：AgentHub 能以 MCP client 身份连接 2026-07-28 下游服务端，同时与
2025-11-25 及更早服务端完全向后兼容。详见英文原文 §2。

### Phase 2 — MRTR（目标：2 週）

目标：下游服务端返回 `InputRequiredResult` 时，正确处理而非作为错误透传。
MRTR 协调器位于 `internal/downstream`（或独立的 `internal/mrtr` 包）。
详见英文原文 §2。

### Phase 3 — 订阅与 OAuth（目标：1 周）

目标：`subscriptions/listen` 取代 GET 通知流；OAuth 与 2026-07-28 认证规范
新增内容对齐。详见英文原文 §2。

---

## 3. 向后兼容策略

| 场景 | 行为 |
|------|------|
| 下游服务端使用 2026-07-28 | `Handshake` → `Discover`，无状态 `_meta` 路径，无 `initialize` |
| 下游服务端使用 2025-11-25 | `Handshake` → method-not-found → `initializeLegacy`，旧有 session/resume 路径 |
| 下游服务端使用 2025-03-26 | 同 2025-11-25 回退路径 |
| 上游客户端使用任意版本 | 网关暴露侧（server 面）本分支不作修改 |

## 4. 测试服务端策略

截至 2026-07-30，尚无主流 MCP server 正式发布 2026-07-28 支持。

### 4.1 进程内 Go stub（主要）

`test/mcpstub/` 中的最小 `net/http` server，实现测试套件所需的新协议面：
`server/discover`、无状态 `tools/call`、一轮 `InputRequiredResult`、
`subscriptions/listen` SSE 流。零外部依赖，作为 `go test ./...` 的一部分构建。

### 4.2 Go SDK beta

```bash
go get github.com/modelcontextprotocol/go-sdk@v1.7.0-pre.1
```

用于 `//go:build integration` 标记的集成测试，对照参考实现进行校验。
不计入 `make ci`（CI 无网络访问）；本地通过 `make e2e-integration` 运行。

### 4.3 Python SDK beta（可选）

```bash
pip install "mcp==2.0.0b1"
```

`test/pyserver/` 中的 Python 脚本作为 Docker e2e 套件的子进程运行，用于跨语言
互通性校验。通过 `TEST_PYSERVER=1` 启用。

## 6. 待定问题 / 延迟决策

1. **`ProtocolVersion` 常量的切换时机**：~~在 Phase 1 传输变更完成并测试套件全绿后，
   作为 Phase 1 最后一个 commit 切换到 `Version2026`。~~
   **已决议（Phase 1 落地时）：该常量永不切换。** 它的每一个使用处在定义上都属于
   2026 之前的协议：legacy initialize 声明（只在 `server/discover` 失败后才运行）、
   暴露侧的默认应答（§3 明确本分支不改）、协商前的 HTTP 头、fakemcp 的脚本默认值。
   2026-07-28 的声明由 `transport.BuildRequestMeta` 直接从 `Version2026` 构造，随
   每个请求的 `_meta` 携带，全局切换只会改错那些本应保持 2025-11-25 的位置。
   详见 `internal/mcp/version.go` 常量注释。
2. **MRTR `sampling/createMessage` 处理**：AgentHub 目前不路由 LLM 调用，返回
   `MissingRequiredClientCapabilityError (-32021)`，并在发送给下游服务端的
   `clientCapabilities` 中不声明 `sampling`。
3. **`tasks` 扩展**：本分支不实现，待扩展规范 GA 后通过后续分支跟进。
4. **暴露侧的 `CacheableResult`**（AgentHub 作为 MCP server 面向上游客户端时）：
   Phase 1 不实现，Phase 3 或后续添加。
